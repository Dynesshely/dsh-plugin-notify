# Session Notifier · 会话提醒

一个 DSH profile 插件（bundle）。安装后，**任意会话**出现下列情况时都会用声音 + 桌面通知提醒你：

| 触发 | 说明 |
|---|---|
| 需要你交互 | 工具审批（approval）、`ask_user_question` 提问、计划审阅（plan review）出现时——立刻提醒 |
| 真正停下来等你 | 该会话不再自己往下走了（**不是**「一轮结束」就提醒） |

「一轮结束」不等于「轮到你」。目标循环、定时任务、排队续跑这类工作每一轮都会结束一次轮次，而宿主会立刻自己开下一轮：**所以你只在会话真正闲下来时才收到提醒。** 判定见下面「怎么算真正停下来」。子代理自身的会话结束同样不提醒（理由见下）。

子代理自己的会话结束时**不提醒**：它是主会话派出去干活的，主会话还在运行，结果会由主会话自己汇报——每完成一个子代理就响一声纯属噪音。但子代理**停下来提问或要审批**时照常提醒，因为那时只有你能推动它，主会话很可能正卡在等它。判定依据是会话目录里的 `origin: 'subagent'`（DSH 自己给子代理会话打的标记），不猜标题、不看父链，所以从子代理会话分叉出来的普通会话仍然会提醒。

已经在看着该会话（窗口有焦点且该会话就在主视图）时不打扰；切到别的窗口、或别的会话结束时照常提醒。

## 怎么算「真正停下来」

一轮结束只是一个**候选**，插件不当场提醒，而是把它按住看接下来发生什么：

- **会话又跑起来了** → 那是循环在续跑，丢掉，不提醒。
- **目标又推进了一轮** → 同上（客户端可能没看到中间那次「运行中」，只看到目标轮次前进了，这条规则专门兜住这种合并更新）。
- **目标还在进行中** → 再多等一会儿（15 秒），期间轮次没有再前进才提醒。这是给「目标轮次之间要等一次落盘检查点」留的余量；否则一个卡住的目标会让它的会话永远不提醒你。
- **目标已完成 / 已暂停 / 已受阻，或根本没有目标** → 等 1.2 秒确认没有动静就提醒。

两个窗口来自实测，不是拍脑袋。从本机 200 多个会话的持久化日志里，按「谁唤醒了下一轮」分组量了 `turn/end` → 下一次 `turn/start` 的间隔：

| 唤醒来源 | 样本 | p50 | p99 | 最长 |
|---|---|---|---|---|
| 目标轮次续跑 | 110 | 12 ms | 24 ms | 115 ms |
| 子代理结算唤醒父会话 | 9 | 169 s | 533 s | 533 s |
| 人类输入 | 1827 | 5 分钟 | 4.3 天 | 23 天 |

目标续跑快在毫秒级，所以 1.2 秒窗口能 100% 吃下它；子代理结算那种几分钟的间隔是父会话**真的空闲**在等子代理，提醒它本来就该发生，不该被窗口吞掉。15 秒那个窗口只在「目标还在进行中、却迟迟没有推进」时生效，是给落盘检查点和慢机器留的余量。

另一个好处：焦点判定在投递时才求值，所以一个拖着没提醒、最后你已经在看它的会话，不会再打扰你。

## 触发信号来自哪里

插件的客户端半边订阅 `ctx.uiSession.sessionStatus` —— DSH 客户端已经为每个会话聚合好的根投影，它同时给出三件事：

- `pendingInteraction`：该会话当前等待用户的交互（审批 / 提问 / 计划审阅）；
- `running`：宿主上报的 Agent 运行状态；
- `completionUnread`：该会话不在屏幕上时完成的轮次（DSH 自己的「未读完成」标记）。

插件对这份投影做前后快照 diff：新增 `pendingInteraction` → 交互提醒（立刻发）；`running` 由 true 变 false（或新增 `completionUnread`）→ 完成候选，走进上面那套「真正停下来」的判定。它不逐个会话订阅，所以一个你从未打开过的会话（别的窗口新建的、从别处分叉出来的）完成时同样会提醒。

目标状态来自会话目录行上的 `projectionValues.goal`（`phase` 与 `roundsStarted`）。这份投影由会话控制器的控制基线一次性下发给整个列表，所以读它是纯本地的，不需要额外请求。

同一批次里若某会话既要提醒完成又有待交互，只提醒交互（完成本来就是因为它停下来等你）。完成候选会先查会话目录的 `origin`，命中 `subagent` 就跳过（见开头说明）；查不到或目录读取失败时一律按普通会话处理，宁可多提醒也不漏提醒。

## 提醒方式

- **提示音**：Web Audio 实时合成，不带音频资源。交互提醒是两声上行短音，完成提醒是两声更柔和的音；900ms 冷却，避免一批完成变成警报器。浏览器的 AudioContext 需要一次用户手势才能出声，因此插件会在你第一次点击/按键时创建并恢复它。
- **桌面通知**：走页面的 `Notification` API（Electron 窗口内即系统通知；普通浏览器同样生效）。权限会在你第一次点击/按键时申请一次，也可以在设置里手动触发。
  - 通知图标是**内嵌的 DSH 应用图标**（`resources/icon.png` 缩到 96×96，base64 编进 `client.js`），所以不依赖任何页面资源路由。
  - 所有通知都带 `requireInteraction`（横幅留在屏幕上，不会几秒后消失）。
  - 每条通知的 tag 都是**唯一且不超过 16 字符**的，并且同一会话的上一条会先被 `close()` 掉。两条 Windows 规则决定了这个设计：① tag+group 已存在于操作中心的 toast 会被**静默替换、不弹横幅**（操作中心跨应用重启仍在）；② `ToastNotification.Tag` 上限 16 字符，超长的 tag 会让 Windows 拒绝这条 toast——而渲染进程完全看不到这个失败（`new Notification()` 照样成功）。早期版本用「会话 id 拼 tag」既长又固定，正好同时踩中这两条，表现为「设置里点测试能弹、真实提醒只响不弹」。

## 设置

**设置 → 通用 → 会话提醒**：

- `提示音`、`桌面通知` 开关
- `正在查看该会话时不提醒`（默认开）
- `允许桌面通知`：手动申请权限
- `测试提醒`：立刻放一次提示音并发一条测试通知（同时完成音频解锁与权限申请）
- `10 秒后测试`：点完可以切到别的窗口，10 秒后触发一次与真实提醒完全相同的链路（声音 + 系统通知），用来验证失焦时提醒是否照常到达
- 行末的诊断文字：`运行环境：… · 通知接口：… · 通知权限：… · 上次提醒：<时间> <结果><发送时窗口状态>`

  例：`运行环境：DSH 桌面应用窗口 · 通知接口：可用 · 通知权限：已授权 · 上次提醒：12:03:45 已发送桌面通知（发送时窗口失焦）`

  没弹出通知时，这一行会直接说明原因（开关关了 / 没权限 / 环境不支持 / 创建失败 / 因为正在查看该会话而跳过），并记录发送那一刻窗口是聚焦、失焦还是不可见。

偏好保存在浏览器 `localStorage` 的 `dsh.session-notifier.v1`。

## 兼容与降级

- 没有 `Notification` API 或权限被拒：只保留提示音，设置行会说明原因。
- 从没和页面交互过（没有任何手势）：浏览器不允许出声，通知一般也申请不到——点一下页面即可。
- 页面关闭时不会有提醒（提醒由页面内的事件驱动）。

## 文件

| 文件 | 作用 |
|---|---|
| `package.json` | bundle 清单：`dsh.bundle.patch` + `dsh.client`（`platform: web`、`immediately: true`） |
| `cordis.patch.yml` | 向 profile 插入插件行 `session-notifier` |
| `index.js` | Host 半边，空实现 |
| `client.js` | 浏览器半边：订阅会话状态、判定是否真的闲下来、响铃、发桌面通知、注册设置行 |
| `locale/en.json`、`locale/zh.json` | 插件管理页显示的标题与描述 |
| `tools/` | 行为测试与阈值复算脚本（见下） |

决策表 / 接线测试位于 `tools/test-session-notifier.mjs`：

```bash
node clients/desktop/session-notifier/tools/test-session-notifier.mjs
```

它用可控时钟驱动，所以「按住再看」的判定可以被逐条钉住。

上面那两个窗口的数字可以用 `tools/probe-round-cadence.mjs` 复算：

```bash
node clients/desktop/session-notifier/tools/probe-round-cadence.mjs
```

它读取 `~/.dsh/sessions` 下的会话日志（每行是一个独立 zstd 帧，`tools/lib/session-log.mjs` 负责分帧解压），统计 `turn/end` → 下一次 `turn/start` 的间隔，并按续跑的来源分类。

## 卸载

设置 → 插件 → 卸载 `Session Notifier`（`@local/dsh-session-notifier`）即可，不会再有任何提醒。
